# Пользовательская документация SARRAG

## Что такое SARRAG?

SARRAG — это система семантического поиска и чата с вашими документами. После загрузки файлов (PDF, DOCX, исходный код, тексты) система индексирует их и предоставляет следующие возможности:

- Поиск по смыслу, а не только по ключевым словам
- Вопросы к чату с ответами на основе содержимого документов
- Управление проектами и пользователями (для администраторов)

**Важно:** все данные хранятся исключительно на вашем сервере. Облачное хранение не используется.

## 1. Первый вход

### Демо-режим (без регистрации)

1. Перейдите на главную страницу
2. Нажмите кнопку **Try Demo**
3. Вы будете перенаправлены в интерфейс поиска

| Параметр | Значение |
|----------|----------|
| Максимальный размер файла | 2 МБ |
| Время хранения файлов | 30 минут (автоудаление) |

### Полноценная версия (CE / Pro / Enterprise)

1. Администратор создаёт учётную запись (логин и пароль)
2. Выполните вход на странице `/login`
3. После авторизации становятся доступны разделы:

| Раздел | Доступность |
|--------|--------------|
| Search | все пользователи |
| Upload | все пользователи |
| Chat | при включённом LLM (Pro/Enterprise) |
| Admin | только администраторы |

## 2. Загрузка документов

### Процедура загрузки

1. Перейдите в раздел **Upload**
2. Перетащите файлы в область загрузки или выберите через диалоговое окно

### Поддерживаемые форматы

| Категория | Форматы |
|-----------|---------|
| Документы | PDF (с OCR для сканов), DOCX, TXT, MD |
| Исходный код | .py, .rs, .js, .go, .json, .yaml, .toml, .ini, .cfg |
| Таблицы | .csv |

### Ограничения

| Режим | Лимит |
|-------|-------|
| Демо-режим | 2 МБ на файл |
| CE (бесплатная версия) | 50 документов на проект |
| Pro / Enterprise | без ограничений (согласно лицензии) |

### Этапы обработки после загрузки

1. **Извлечение текста**  
   - PDF: pdfplumber  
   - Сканированные PDF: OCR через unstructured

2. **Разбивка на чанки**  
   Учитываются заголовки, списки, таблицы

3. **Векторизация**  
   Модель BGE-M3 (dense + sparse эмбеддинги)

4. **Сохранение**  
   - Векторная база: Qdrant  
   - Метаданные: PostgreSQL

> Прогресс загрузки и обработки отображается в реальном времени через SSE (Server-Sent Events).

## 3. Поиск документов

### Интерфейс поиска

Перейдите в раздел **Search**.

#### Стандартный поиск

1. Введите поисковый запрос (поддерживается 100+ языков)
2. Нажмите кнопку **Search**
3. Система возвращает топ-5 наиболее релевантных фрагментов

#### Состав результатов

Каждый результат поиска содержит:

| Поле | Описание |
|------|----------|
| Фрагмент текста | Контекст из документа |
| Источник | Название документа, номер страницы |
| Score | Оценка релевантности |
| Детализация | Вклад dense / sparse / rerank (при включённом Explain) |

### Расширенные настройки

| Опция | Назначение |
|-------|------------|
| Explain relevance | Детальная разбивка итоговой оценки релевантности |
| Фильтр по документу | Ограничение поиска конкретными файлами (параметр `doc_filter` в API) |
| Низкокачественные чанки | Отображение фрагментов с низкой оценкой качества (обычно скрыты) |

### Оценка релевантности (фидбек)

Под каждым результатом поиска доступны кнопки оценки:

- **👍** — положительная оценка
- **👎** — отрицательная оценка

**Назначение:** улучшение ранжирования и сбор статистики.  
**Привязка:** оценки сохраняются в контексте текущего проекта.

## 4. Чат с документами

### Доступность

Раздел **Chat** доступен при выполнении одного из условий:

- Установлена лицензия Pro или Enterprise
- Функция включена вручную администратором

### Сценарий использования

> **Пользователь:** Какие требования к серверу для установки?
>
> **Ассистент:** Согласно разделу 4.2 технической документации (requirements.pdf, стр. 8):
>
> Минимальные: 2 CPU, 4 GB RAM, 20 GB HDD
>
> Рекомендуемые: 8+ CPU, 16 GB RAM, GPU 8+ GB VRAM

### Особенности работы

1. Система находит релевантные фрагменты документов
2. Фрагменты передаются в LLM
3. LLM генерирует ответ с **цитированием источников** (документ + страница)
4. Чат сохраняет **последние 5 сообщений** для поддержки диалога

### Пример диалога

> **Пользователь:** Опиши процедуру резервного копирования.
>
> **Ассистент:** Согласно разделу 3.2 документации (`backup_guide.pdf`, стр. 12), резервное копирование выполняется командой:
> ```bash
> ./backup.sh --full
> ```
> Рекомендуемый срок хранения резервных копий — 30 дней.

## 5. Управление проектами

### Общая информация

- Переключатель проектов расположен в верхней части страницы
- Проект по умолчанию: **Default Project**
- Каждый проект полностью изолирован (документы, поиск, чат, фидбек)

### Действия с проектами

| Действие | Кто выполняет | Где |
|----------|---------------|-----|
| Создание проекта | Администратор | Admin → Projects |
| Удаление проекта | Администратор | Admin → Projects |
| Загрузка документов в проект | Любой пользователь | Upload (с выбором проекта) |
| Переключение между проектами | Любой пользователь | Верхняя панель |

## 6. Администрирование

**Доступ:** только для пользователей с ролью `admin`.  
**Раздел:** Admin.

### Вкладка Overview

#### Блок статистики

| Метрика | Описание |
|---------|----------|
| Количество документов | Общее число загруженных документов |
| Количество чанков | Общее число фрагментов в индексе |
| Количество запросов | Всего выполненных поисковых запросов |
| Количество фидбеков | Всего оценок (👍/👎) |
| Средняя задержка | Среднее время ответа системы |

#### Графики и визуализация

- Динамика запросов по времени
- Соотношение лайков и дизлайков
- Перцентили задержек (p50, p95, p99)
- Топ документов по частоте извлечения

#### Конфигурация

| Параметр | Описание |
|----------|----------|
| Веса dense/sparse | Настройка вклада разных типов эмбеддингов |
| Reranker | Включение/отключение этапа переранжирования |
| Размер чанка | Количество токенов/символов на фрагмент |

#### Инспектор чанков

- Просмотр всех фрагментов в системе
- Фильтрация по: документу, типу, уровню уверенности

### Вкладка Users

| Функция | Описание |
|---------|----------|
| Список пользователей | Просмотр всех зарегистрированных пользователей |
| Создание пользователя | Добавление нового пользователя (логин/пароль) |
| Удаление пользователя | Удаление существующей учётной записи |

> **Примечание:** максимальное количество пользователей определяется лицензией.

### Вкладка Projects

| Действие | Примечание |
|----------|------------|
| Создание проекта | Новый изолированный проект |
| Удаление проекта | Проект `default` удалению не подлежит |

### Вкладка License

Отображаемая информация:

| Параметр | Описание |
|----------|----------|
| Tier | CE / Pro / Enterprise |
| Срок действия | Дата окончания лицензии |
| Максимумы | Лимиты по документам, пользователям, запросам |

**Смена лицензии:** запрос нового ключа у вендора.

## 7. Часто задаваемые вопросы (FAQ)

### Вопрос: возможна ли работа SARRAG без доступа к интернету?

**Ответ:** Да. Все компоненты работают полностью офлайн при условии локальной загрузки моделей эмбеддера и LLM.

---

### Вопрос: какие требования к серверному оборудованию?

**Ответ:** Минимальные и рекомендуемые конфигурации:

| Компонент | CE (минимально) | Pro/Enterprise (рекомендовано) |
|-----------|-----------------|-------------------------------|
| CPU | 2 ядра | 8+ ядер |
| RAM | 4 GB | 16 GB |
| Диск | 20 GB HDD | SSD (объём по необходимости) |
| GPU | не требуется | 8+ GB VRAM (для LLM) |

---

### Вопрос: как выполнить обновление системы?

**Ответ:** Последовательность действий:

1. Остановите запущенные контейнеры
2. Замените Docker-образы на новые версии
3. Выполните миграции базы данных:

```bash
alembic upgrade head
```

---
### Вопрос: можно ли интегрировать SARRAG со сторонним приложением?
**Ответ:** Да. Система предоставляет полноценный REST API. Подробная документация для разработчиков доступна отдельно.
